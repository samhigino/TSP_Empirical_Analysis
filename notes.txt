Vamos desenvolver um projeto que consiste em estudar três soluções para o Problema do Caixeiro Viajante Simétrico. O nosso projeto será desenvolvido em Python 3.13, e deve resolver o TSP para algumas instâncias de 3 formas diferentes:

1- Usando um algoritmo exato baseado em Branch-and-Bound;
2- Usando o algoritmo aproximado Twice-around-the-tree;
3- Usando o algoritmo aproximado de Christofides.

Para o Branch-and-Bound, iremos tentar implementar algumas heurísticas geradoreas de soluções para inicializar o limite superior da árvore de busca (warm-start). As estratégias de inicialização que devemos implementar são:

1- Trivial: Inicializar com a solução ingênua (1 -> 2 -> 3 -> ... -> N);
2- Busca Gulosa: Heurística do vizinho mais próximo (Nearest Neighbor);
3- Heurística de Inserção Baseada em Fecho Convexo (Convex Hull): a sub-rota inicial corresponde ao fecho convexo das cidades, e os vértices internos são inseridos de forma gulosa;
4- Twice-around-the-Tree: Usa o resultado desta aproximação como limite inicial;
5- Christofides: Usa o resultado desta aproximação como limite inicial;

Os outros dois algoritmos serão implementados da maneira convencional. Você pode usar as bibliotecas NumPy, SciPy, Scikit-learn e Pandas, além das bibliotecas padrão. Bibliotecas para grafos (Networkx, iGraph) são permitidas desde que seja estritamente para suporte e que seja possível que os gargalos computacionais (como perfect matcing e árvore geradora mínima) sejam submetidos a profiling de tempo e memória em nível de subrotina.

A implementação seguirá um approach voltado à modularização. Assuma que a estrutura do projeto será a seguinte:
TSP_Empirical_Analysis/
|- data/
|  |- ... (instâncias do TSP)
|- raw_ai_scripts/
   |- branch_and_bound.py
   |- twice_around_the_tree.py
   |- christofides.py
   |- main.py
   |- data_convert.py

Aqui está a explicação do que deve ocorrer em cada um dos nossos scripts:

1- branch_and_bound.py: deverá implementar o algoritmo de branch and bound via alguma função, e deve implementar todas as 5 heurísticas, cada uma em uma função separada que retorna o limite inicial para o algoritmo. A função principal do branch_and_bound deve receber um parâmetro que indica qual heurística devemos usar. A função principal também deve manter um cronômetro durante toda a sua execução para monitorar o tempo, e o algoritmo deve parar caso o tempo exceda um limite de 30 minutos. Quando o algoritmo parar, seja porque encontrou a solução ótima ou porque o tempo limite foi estourado, a função deve retornar:
    - O tempo total de execução do algoritmo (deve tratar o caso especial em que o tempo limite foi excedido);
    - O tempo de execução da heurística para geração do limite inicial;
    - O valor da melhor solução encontrada (ótima caso o tempo decorrido seja <30min);
    - O número de nós expandidos;
    - O número de nós podados.
Ps.: NÃO implemente este algoritmo usando uma busca em largura.

2- twice_around_the_tree.py: deverá implementar o algoritmo aproximativo twice-around-the-tree. A função que implementa o algoritmo receberá o valor da solução ótima como parâmetro, para que, ao final, ela possa calcular o fator de aproximação. Assim como o branch-and-bound, a função deverá manter conta do tempo decorrido durante a execução do algoritmo. Aqui também devemos ter um limite de 30 minutos de execução, mas como o algoritmo é polinomial, espera-se que este limite nunca seja excedido. A função deve retornar:
    - O tempo total de execução do algoritmo. Como o algoritmo é polinomial, não deve nem chegar perto do limite, então, caso exceda o limite de 30 minutos, a função deve lançar uma exceção;
    - O fator de aproximação.

3- christofides.py: deverá implementar o algoritmo aproximativo de christofides. A função que implementa o algoritmo receberá o valor da solução ótima como parâmetro, para que, ao final, ela possa calcular o fator de aproximação. Assim como os outros, a função deverá manter conta do tempo decorrido durante a execução do algoritmo. Aqui também devemos ter um limite de 30 minutos de execução, mas como o algoritmo é polinomial, espera-se que este limite nunca seja excedido. A função deve retornar:
    - O tempo total de execução do algoritmo. Analogamente ao twice-around-the-tree, deve-se lançar uma exceção no caso de limite de tempo excedido;
    - O fator de aproximação.

4- data_process.py: este script será responsável por interpretar os aquivos de dados das instâncias, para que a saída seja palatável ao resto do código. Mais à frente eu explico de onde vêm as instâncias e como são os arquivos. A função deve receber o nome do arquivo e retornar um grafo (da maneira que preferir) correspondente à instância lida;

5- main.py: este será o script que deve ser executado para a nossa análise. Este script deve, para cada instância que selecionamos do problema:
    5.1- Evocar data_process para interpretar os dados;
    5.2- Chamar os scripts de cada solução e coletar os dados retornados por cada um. Devemos escolher apenas um dos warm-starts possíveis para executar o branch-and-bound, e isso pode ser pré-definido usando, por exemplo, o valor de uma variável global no cabeçalho do script;
    5.3- Tendo resolvido a instância de todas as maneiras, gravar os dados das execuções dela em um arquivo à parte (por exemplo, em formato json para facilitar a leitura depois). Para cada instância, devemos guardar todos os dados retornados por cada uma das funções chamadas (tempo decorrido, fator de aproximação, tudo que está especificado no script de cada algoritmo), evidenciando qual warm-start usamos para o branch-and-bound.
Tendo feito isso para todas as instâncias selecionadas, devemos ajustar os tempos coletados (em função do número de nós N) a curvas teóriacas de complexidade espacial e temporal. Especifique métricas de ajuste (R² ou RMSE) e grave os resultados em um arquivo também.

Nota: como dito anteriormente, caso você opte por usar alguma biblioteca para grafos, as funções que a usarem também devem retornar (ou ao menos imprimir) o profiling de tempo e memória das subrotinas utilizadas.
